🚀 Quick Start & VPS Installation Guide

Get up and running on AWS EC2, DigitalOcean Droplets, Hostinger, Azure, or private servers in less than 3 minutes.

Setup Instructions
  1. Run the installation script: Connect to your VPS server via SSH and execute the installer: 
    curl -sSL https://raw.githubusercontent.com/ktbsomen/cicd/main/install.sh | sudo bash
  2. Register your application: Run the orchestrator with your repository configuration: 
    sudo cicd --repo "https://github.com/user/express-app" --branch "main"
  3. Grab the Setup Token: The orchestrator will dynamically print a **Setup Token** in the console. Copy this token!
  4. Connect the webhook: Log into the onboarding web dashboard (Port 8080 or your custom port) using the token, and copy the GitHub Webhook configurations. Paste it inside GitHub -> Settings -> Webhooks.

📦 The .cicd Directory & Scripting Standards

How to structure your scripts inside the codebase to achieve automated builds, background executions, and active health checks.

1
install.sh

Runs under root JIT NOPASSWD privileges. Perfect for package installations (npm, yarn, cargo, python) and system configurations.

#!/bin/bash
# set -e / pipefail is auto-patched!
npm install
2
run.sh

Runs under restricted service user credentials. Spawns your application process or passes execution to process managers.

#!/bin/bash
# Run express server
node index.js
3
health.sh

Runs independently with a 10s timeout. Validates application startup and handles ongoing background loops.

#!/bin/bash
# Test endpoint response
curl -f http://localhost:3000/

⚡ The 4-Tier Process Lifecycle

The orchestrator is extremely flexible. It auto-detects how your script executes and implements appropriate watchdogs.

Tier Mode Description PID Monitoring Watchdog Recovery
Tier 1: Blocking Command runs in foreground (default). Go tracks cmd process directly. Automated Restarts
Tier 2: Background Script runs command in background with &. PGID (Process Group) tracking. Automated Restarts
Tier 3: Delegating Script outputs process PID to $CICD_PID_FILE. Active PID file monitoring. Automated Restarts
Tier 4: External Detached daemons (e.g. PM2, tmux session, docker). SQLite Fallback / health.sh Loop Custom Loop Watchdog

🛡️ Multi-Tenant Privilege Isolation & Drops

We take security extremely seriously. Production applications should never run as root.

👤 Dynamic Privilege Dropping

When you register a service under a specific --service-user, the orchestrator performs a secure OS credential drop (UID/GID transition) before launching `run.sh`.

⚠️ Crucial: HOME and USER env variables are overridden to prevent process config leakage into the root user structure.

🔑 JIT NOPASSWD Privilege Management

Our orchestrator separates dynamic managed users (NOPASSWD) from existing system accounts. Sudoers rules are configured temporarily only for the duration of installation builds and removed immediately after!

PID file and workspace ownership are aligned recursively to resolve permissions denied (EACCES) crashes automatically.

🔧 Local Development Testing & CLI Commands

Bypass network constraints during testing and view complete administrative commands list.

Local Test Mode

If you are developing or testing the orchestrator on a local machine (or behind a NAT firewall without a public IP), you can skip dynamic public IP resolution from ipify by passing: 

sudo cicd --public-ip 127.0.0.1

This configures the payload interfaces and setup instructions to bind strictly to localhost, making local testing completely painless.

CLI Commands Reference

View all registered command-line operations by running:

cicd commands
  • cicd list: List registered applications
  • cicd info: Show Webhook setup and payload URLs
  • cicd token: Grab setup token for dashboard authentication
  • cicd history <svc>: View deployment commits history
